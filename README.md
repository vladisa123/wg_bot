# wg-bot

Telegram-бот раздачи VPN-конфигов: **AmneziaWG** и **Shadowsocks**.
Пользователь жмёт «Создать конфиг» → выбирает протокол → вводит имя —
бот генерирует ключи, добавляет пира в `awg0.conf` на VPN-сервере (по SSH)
и присылает `.conf`/`ss://` ссылку.

## Почему AmneziaWG вместо WireGuard

WireGuard на направлении до румынского сервера режется DPI: handshake проходит,
но data-пакеты дропаются — VPN «подключён», а интернета нет. Лечится только
сменой сети. AmneziaWG добавляет junk-префикс и меняет размеры пакетов,
поэтому сигнатура не совпадает и трафик проходит.

Клиенту нужен **AmneziaWG-клиент**, а не обычный WireGuard.

## Устройство

- `bot.ts` — весь бот на Deno, один файл, без зависимостей
- `clients.json` — выданные конфиги (имя, tg_id, IP, ключи)
- `names.json` — соответствие tg_id → имя
- `whitelist.json` — кому разрешено создавать конфиги
- `requests.json` — заявки на доступ

## Поток создания конфига

```
➕ Создать конфиг → 🔧 выбор протокола → ✏️ имя → ✅ готовый конфиг
```

## Запуск

```bash
cp .env.example .env   # заполнить
set -a && . ./.env && set +a
deno run --allow-all bot.ts
```

Как systemd-сервис — см. `wg-bot.service`.

## Переменные окружения

| Переменная | Смысл |
|---|---|
| `WG_BOT_TOKEN` | токен бота от @BotFather |
| `WG_BOT_ADMIN` | Telegram ID админа |
| `WG_SSH_HOST` | хост VPN-сервера (`127.0.0.1`, если бот на том же сервере) |
| `WG_ENDPOINT` | `IP:порт` для клиентских конфигов |
| `WG_SERVER_PRIVKEY` | приватный ключ сервера |
| `WG_SERVER_PUB` | публичный ключ сервера |
| `WG_PSK` | PresharedKey (общий для пиров AmneziaWG) |
| `WG_POSTUP` | опциональный PostUp |

Все секреты задаются только через `.env`. В коде дефолтов нет намеренно.

## Важно

- Бот правит `/etc/amnezia/amneziawg/awg0.conf` **на VPN-сервере** через SSH.
  Если бот стоит на том же сервере — `WG_SSH_HOST=127.0.0.1` и ключ в
  `/root/.ssh/authorized_keys`.
- Параметры обфускации (`Jc/Jmin/Jmax/S1/S2/H1-H4`) должны совпадать
  у сервера и клиента — они задаются в `AWG_BLOCK`.
- В `writeRemoteConf` есть защита: конфиг с меньшим числом пиров, чем живёт
  сейчас, не заливается — иначе `awg syncconf` снесёт всех клиентов.
